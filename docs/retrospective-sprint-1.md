## 4. Presentation Feedback and Our Response

We earned **47.40/50** on Presentation 2. The feedback praised our working features and teamwork. It also pointed out things we need to improve.

### Burndown Chart and UML Diagrams

**Staff comment:**  
> "the detailed burndown chart and addition of the UML diagrams"

**Our plan:** We will update the burndown chart during Sprint 2 and add UML diagrams to explain our features in the next presentation.

### Communication Through Teams

**Staff comment:**  
> "please switch to teams for discussion about the project so TA and me can be involved."

**Our plan:** We will use Teams for meetings and progress updates so the professor and TA can follow our work and offer help.

### Pull Requests and GitHub Updates

**Staff comment:**  
> "The one thing holding you back is merging."

All five members submitted pull requests. However, at the time of the review, 16 of 20 pull requests were still open, and none of the 10 Sprint 1 issues were closed.

**Our plan:** We will review ready pull requests within one or two days, merge approved code, close finished issues, and update the tracker. We will also remove unused branches after checking them, add a `.gitignore` if needed, and write clearer setup instructions in the README.

### Matching and Messaging

**Class feedback:**  
> "The open question is the matching itself"

Classmates liked the profiles, login, and suggested-users page. However, they were unsure how matching worked and whether matched users could contact each other.

**Our plan:** We will test matching different skills and clearly show why users match. In Sprint 2, we will also work on sending, accepting, and rejecting requests and messaging other users.

### Bugs and Security

Classmates noticed that email verification was missing and that users could appear in their own suggested users lists. They also raised questions about profile privacy and SQL injections.

**Our plan:** We will check and fix self-suggestions, check who can view profiles, and make sure database queries handle user input safely. We will also discuss how to add email verification and estimate the work needed.

### Understanding Our Code

The TA reminded us that we must understand our code, even when using AI tools.

**Our plan:** Each member will check and test their code and be ready to explain it. If someone does not understand part of the code, they will ask for help before it is merged.
